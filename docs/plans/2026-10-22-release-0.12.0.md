# Release 0.12.0 plan

**Goal:** ship the design refresh and everything since 0.11.1 as 0.12.0 on GitHub, PyPI, ghcr, the MCP Registry and the
Chrome Web Store, with the README, the guide and the website showing the new screens. Nothing a user sees should be
older than the app.

**Source of truth:** `docs/RELEASING.md` (the checklist). This plan is the 0.12.0 run of it plus what is specific to
this release.

## What ships

- **Version 0.12.0, a minor.** It carries migrations and API shape changes, and `CHANGELOG.md` already lists them
  under `### Breaking changes`. Before 1.0 that is a minor, not a patch.
- **Scope: 134 commits since `v0.11.1`**, none of them through GitHub CI yet:
  - career-history wordings and Tidy bullets;
  - one app-neutral prompt per automation;
  - the Agent inbox Select mode;
  - the design refresh (Today, Setup, Jobs, job page, Analytics, Profile, Settings, countries and money, motion);
  - the frontend de-duplication.
- **Migrations:** `349b494103b9 → c5b4833bcc54` (`jobs.country_code`, `jobs.salary_currency_assumed`,
  `application_status_events`), plus the career-history ones before them. Checked on a copy of real data on
  2026-10-22. The owner's live app has run them since then as 0.12.0.dev3.

## Phase 1: pre-release fixes (on a branch, before CI)

1. **Pin or adapt for openai 3.x.**
   - The problem: `pyproject.toml` says `openai>=1.54` with no ceiling, and CI installs the newest allowed versions,
     not the lock. A fresh venv now gets openai 3.36.1, and there
     `tests/test_http_client.py::test_after_the_repair_the_openai_sdk_and_a_child_process_build_their_clients` fails:
     its premise ("the SDK rejects a malformed NO_PROXY entry") no longer holds. So CI will fail.
   - The default fix: adapt, don't pin. The owner's live install already runs openai 3.28.0 without trouble (checked
     2026-10-22), so a `<3` ceiling would downgrade every install. Check whether `services/http_client`'s NO_PROXY
     repair still matters under 3.x. Then rewrite the test's premise to the SDK's real 3.x behaviour, keeping the 2.x
     branch while the lock pins 2.53.0. Add a `<4` ceiling at most.
   - Either way, run the full suite in a CI-like venv (`uv venv -p 3.12` then `uv pip install -e ".[dev,mcp]"`; uv is at
     `~/.langflow/uv/uv`) to catch any other newest-dependency failure.
2. **Lock vs pyproject.** `backend/requirements.lock` must match `pyproject.toml` (RELEASING step 3). Regenerate only if a
   floor or ceiling moved (step 1 above would move one).
3. **A live ECB fetch.** On the live app, Settings › Basics › Money › Update. The rate date should be the last ECB
   working day. The cloud build could not reach `www.ecb.europa.eu`.
4. **Browser pass at 1280 and 1024, light and dark** (handoff "Checks still to run", item 7):
   - a fresh stack;
   - an empty data dir for Setup;
   - every refreshed page;
   - the Jobs row → job page morph (open, back, reduced motion).

   The screenshot run (Phase 2) covers light mode at 1920. Dark mode and 1024 still need their own look.
5. **README badge.** "11,900 passing" is stale. Use the CI count of the release commit.

## Phase 4: ship

Auto mode blocks pushes to `main` and tags (Merge Without Review), so the owner runs steps 1 and 5's approval.

1. **Owner:** `git push origin release/0.12.0:main`, then the tag:
   `git tag -a v0.12.0 <release commit> -m "v0.12.0" && git push origin v0.12.0`. Fast-forward local main after.
2. **Images** (`images.yml`): ghcr `0.12.0` and `latest`, amd64 and arm64. Check an anonymous manifest fetch returns 200
   (`DOCKER_CONFIG=<empty dir> docker pull`, so the owner stays logged in).
3. **PyPI:**
   - The owner approves the `pypi` environment. Every publish waits for that review.
   - Then `uv tool install maestro-career-studio==0.12.0` in scratch folders. The CDN may say "no version" for 5 to
     15 minutes.
4. **GitHub Release** from the tag:
   - the CHANGELOG section as notes;
   - `mcpb/maestro-career-studio.mcpb` attached, with its sha equal to `server.json`.
5. **MCP Registry:** the owner publishes with a classic PAT scoped only `read:org`, read with `read -rs`
   (RELEASING 6b). Then check that 0.12.0 is `isLatest`.
6. **Chrome Web Store:** the owner uploads the `extension/` zip at 0.12.0. The Companion changed in this release: a
   paused work-permit answer saves to the job's country, and the Apply link points at Settings › Companion.
7. **Clean install check** on spare ports (`UV_TOOL_DIR`, `MAESTRO_HOME` and ports in scratch, never 8001/3000). It
   should report `0.12.0`, schema `c5b4833bcc54`, and up to date.
8. **Owner's live app:** `uv tool install --force maestro-career-studio==0.12.0`. A dev wheel blocks `maestro update`,
   so this one step is by hand. After that, `maestro update` works again.
9. **Website:** push the media and copy commit (Phase 2 step 4) once PyPI shows 0.12.0.

## Rollback

- **App data:** every `maestro update` saves a verified snapshot first (the live one before 0.12.0.dev3 is
  `backups/db-20261022T074901Z.sqlite3.gz`).
- **A broken release:** publish 0.12.1 with the fix. Tags only go up (RELEASING step 1), so never re-point `latest` to
  an older tag. Yank on PyPI only if an install itself breaks.
- **Website:** Vercel keeps every deploy, so promote the previous one.
